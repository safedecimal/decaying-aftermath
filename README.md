# Decaying Aftermath

Отдельный стартовый мод для **Minecraft 26.3 / Fabric**, Java 25.
## Медицинская система (0.3.0)

Мод устанавливается **на клиент и сервер**; в одиночной игре сервер встроен.
Шесть частей тела, кровопотеря, боль, переломы, дыхание и действие препарата
рассчитываются сервером и сохраняются вместе с таймерами лечения.
Ванильный HP остаётся совместимым отражением состояния, а не второй жизнью.
Обычный урон проходит ванильные щит/броню/сопротивление, затем повреждает тело;
падение прежде всего повреждает ноги. Если точка удара неизвестна, используется
геометрический fallback; точное анатомическое попадание для любого мода не обещается.
Натуральная регенерация от еды и peaceful HP-регенерация игрока отключены.

Инвентарь: медпанель в **(0,0)**, оригинальное тело CU в центре, броня возле
частей тела, 27 настоящих слотов и 9 хотбарных снизу; offhand, крафт и книга
рецептов сохранены. Присланный рисунок — только схема, в ресурсы он не включён.
Вверху медпанели ник игрока; пульс/ЭКГ и сердечки теперь зависят от состояния тела.
Выводятся только подключённые показатели. Монитор, глифы, тело, иконки,
круг бессознательности, Last Standing и записи звуков взяты из установленной CU.

### Лечение

Перетащи лечебный предмет **из обычного инвентаря/хотбара на часть тела**:
- бинт: оберни кольцо по часовой стрелке;
- шина: совмести с конечностью и закрепи двумя ремнями;
- жгут: установи и затяни поворотом;
- шприц: захвати, опусти к игровой коже, введи нужную игровую долю и выведи;
- зелье: поднеси к выбранной части тела и удерживай до завершения процедуры.

Расход и допустимый темп проверяет сервер. Остаток шприца сохраняется в предмете;
отмена не возвращает уже введённое. Применение прямо из результата крафта запрещено
для исключения дюпа — сначала перенеси готовый предмет в инвентарь.
У всех медпроцедур интерактивная мини-игра. У шин и жгутов в CU мини-игр нет,
поэтому их взаимодействия — адаптация с оригинальными ассетами/звуками.

Крафты (бесформенные): 2 любой шерсти → 4 бинта; 2 бинта + нить → давящая
повязка; 2 палки + 2 нити → шина; кожа + нить + железный самородок → жгут.
Книга рецептов открывает рецепты при нахождении основных материалов.
Бинты/шины также встречаются в луте; фентанил — редкий лут храмового сундука
деревни, подземелий и крепостей. Обычного рецепта фентанила нет.

Обычные зелья можно пить удержанием ПКМ **или** применять через медпанель.
Лечебные/регенерирующие правильно применяются на тело: одно зелье — одна процедура.
При питье лечебное зелье расходуется, но лечебные эффекты не работают; после
завершения печатается мысль **`It's seems didn't help..`** в actionbar, примерно
18 символов/с, с оригинальным звуком CU. Прочие эффекты смешанных зелий сохраняются.
Бросаемые и оседающие зелья не превращены в питьевые предметы.

Боль/кровопотеря/передоз могут вызвать потерю сознания: затемнение,
центральная ЭКГ и оригинальная круговая шкала. Очень критическое состояние
включает Last Standing — ограниченный последний шанс с оригинальным интро/звуками;
длительность и физиология адаптированы под мод, не объявляются точной копией CU.
Фентанил временно уменьшает боль, но не чинит ткани и переломы; избыток/повторное
введение может привести к передозу и смерти. Все количества — условные игровые,
без реальных дозировок или инструкций применения.

Инфекции, правый grid-инвентарь, спецверстак препарата и расширенная реанимация —
следующие отдельные этапы. Проверки модели/ресурсов и сборка автоматизированы;
проверку в игровом клиенте выполняет пользователь, агент Minecraft не запускает.

Происхождение и хеши исходных ассетов: `medical_asset_provenance.json` и
`medical_rework_provenance.json` в ресурсах `assets/decaying_aftermath`.
Права на сторонние изображения/глифы/звуки принадлежат исходным владельцам;
эта работа не предоставляет лицензию на их публичное распространение.

## Локальная сборка

```powershell
.\gradlew.bat build
```

Linux/macOS: `./gradlew build`. JAR: `build/libs/decaying-aftermath-<VERSION>.jar`.
Для запуска нужны Minecraft 26.3, Fabric Loader 0.20.1+ и Fabric API для 26.3.

## Автоматические релизы: один номер — одна попытка сборки

Единственный источник версии — файл **VERSION**. Gradle, метаданные мода,
имя JAR, тег и GitHub Release берут номер из него.

1. Для нового релиза поменяй `VERSION`, например с `0.1.0` на `0.1.1`.
2. Закоммить изменения вместе с кодом и пушни в `main`.
3. Actions соберёт JAR и автоматически опубликует его в GitHub Releases.

Обычные пуши без изменения `VERSION` **вообще не запускают workflow**.
Пуши в другие ветки и PR тоже не запускают релизную сборку.
Пробелы/переносы строк в том же номере не разрешают новую сборку.
Возврат к уже использованному номеру запускает только короткую проверку;
**Gradle и публикация пропускаются**, существующий релиз не изменяется.

До запуска Gradle номер атомарно резервируется тегом `v<VERSION>` и создаётся
черновик релиза. Поэтому параллельные пуши не могут пересобрать один номер.
Повторный запуск Actions (`Re-run jobs`, включая failed jobs) не запускает сборку.
Если сборка упала, номер остаётся занятым: исправь причину и увеличь `VERSION`.
Не удаляй и не переставляй релизные теги: они являются журналом использованных номеров.

Формат: `MAJOR.MINOR.PATCH` или `MAJOR.MINOR.PATCH-prerelease`, без префикса `v`
и без build metadata (`+...`). Зависимости меняются в `gradle.properties`, но
сами по себе не запускают публикацию: для релиза также требуется новая версия.

Репозиторий приватный; релизы и JAR доступны только имеющим доступ к нему.
