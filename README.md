# Decaying Aftermath

Отдельный стартовый мод для **Minecraft 26.3 / Fabric**, Java 25.
## Медпанель (0.2.1)

В обычном инвентаре игрока показывается медпанель: **только пульс (BPM) и его
анимированная кривая**. Груз, здоровье мозга, кислород, давление, кровь и прочие
медицинские показатели пока не выводятся. На узком экране или с открытой книгой
рецептов остаётся оригинальная двухстрочная шапка с ником и числом пульса,
не закрывая слоты. Без книги рецептов полная панель помещается даже при ширине GUI 320.

Сердечки над хотбаром обозначают **общее состояние**, а не количество HP.
Пока единственный подключённый показатель — пульс: покой около 72 BPM,
движение/спринт/плавание повышают его, затем он плавно восстанавливается.
Это временная игровая симуляция; модель не использует `getHealth()` и
`getMaxHealth()`. Стандартные урон и смерть Minecraft не изменены.
Броня, еда, воздух и здоровье транспорта остаются стандартными.

Визуальные исходники взяты из установленной **Casualties Unknown**:
оригинальный **`computerBack`** — серая рамка и зелёный CRT-экран, как в референсе.
Чёрный `uiBlock` не используется: его Image в исходном `StatMenu` выключен.
Вместо `EXPERIMENT` в исходной шапке выводится текущий ник Minecraft.
Строка пульса взята из **`screenStatic`**, заголовок и глифы — **`I-pixel-u`**.
Пропорции монитора и исходные места шапки, пульса и ЭКГ сохранены.
Плюсы и весь нижний блок одежды/WEAR убраны. Все неработающие показатели,
их иконки, а также рост/возраст/ID скрыты; на их месте остаётся исходный CRT-фон.
Значок кислорода убран из общего растрового слоя.
Нет добавленных надписей PULSE/BPM, огромного сердца, собственной рамки или
растянутых цифр. ЭКГ сохраняет исходные 120×25 пикселей, круговую развёртку,
28 мс и затухание 0.985 из `ECGVisualizer`.
Медпанель и `ECGVisualizer` изучены через dnSpyEx 6.6.0. Подробности происхождения и хеши —
`src/main/resources/assets/decaying_aftermath/medical_asset_provenance.json`.
Права на эти сторонние изображения/глифы принадлежат их исходным владельцам;
эта работа не предоставляет лицензию на их публичное распространение.

## Локальная сборка

```powershell
.\gradlew.bat build
```

Linux/macOS: `./gradlew build`. JAR: `build/libs/decaying-aftermath-<VERSION>.jar`.
Для запуска нужны Minecraft 26.3, Fabric Loader 0.20.1+ и Fabric API для 26.3.

## Автоматические релизы: один номер — одна попытка сборки

Единственный источник версии — файл **VERSION**. Gradle, метаданные мода,
имя JAR, тег и GitHub Release берут номер из него.

1. Для нового релиза поменяй `VERSION`, например с `0.1.0` на `0.1.1`.
2. Закоммить изменения вместе с кодом и пушни в `main`.
3. Actions соберёт JAR и автоматически опубликует его в GitHub Releases.

Обычные пуши без изменения `VERSION` **вообще не запускают workflow**.
Пуши в другие ветки и PR тоже не запускают релизную сборку.
Пробелы/переносы строк в том же номере не разрешают новую сборку.
Возврат к уже использованному номеру запускает только короткую проверку;
**Gradle и публикация пропускаются**, существующий релиз не изменяется.

До запуска Gradle номер атомарно резервируется тегом `v<VERSION>` и создаётся
черновик релиза. Поэтому параллельные пуши не могут пересобрать один номер.
Повторный запуск Actions (`Re-run jobs`, включая failed jobs) не запускает сборку.
Если сборка упала, номер остаётся занятым: исправь причину и увеличь `VERSION`.
Не удаляй и не переставляй релизные теги: они являются журналом использованных номеров.

Формат: `MAJOR.MINOR.PATCH` или `MAJOR.MINOR.PATCH-prerelease`, без префикса `v`
и без build metadata (`+...`). Зависимости меняются в `gradle.properties`, но
сами по себе не запускают публикацию: для релиза также требуется новая версия.

Репозиторий приватный; релизы и JAR доступны только имеющим доступ к нему.
